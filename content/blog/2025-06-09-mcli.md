Started [mcli](https://github.com/gwicho38/mcli) today — a runner for the scripts I already have.

Every project accumulates them. A backup script, a deploy script, a notebook that answers exactly one question. They scatter, most go undocumented, and the good ones get written a second time (badly) because nobody could find the first.

The frameworks that fix this all ask for the same toll up front. Register the script. Describe it. Give it a manifest, a decorator, a home inside their engine. That's a lot of ceremony to run a file that already works.

So the rule here is: run first, register later. `mcli run ./backup.py` executes the thing exactly as it sits, with tab completion over the paths (including the hidden directories, which is where these things actually live). If a script earns more, register it as a versioned workflow and get scheduling and sharing. If it doesn't, nothing was spent.

Workflows live in `~/.mcli/workflows/`, versioned by a lockfile and decoupled from the engine — portable enough that walking away from this costs nothing.
